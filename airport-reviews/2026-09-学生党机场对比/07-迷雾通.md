# 迷雾通（Geph）：全系列唯一能被你自己查证的一个（2026 年 9 月）

> **一句话结论**：迷雾通不是机场，是一套开源的抗审查接入系统；它的价值不在"节点多快"，而在于两件事——**授权绑定设备而不是账号**（所以"仅限本人"是机制、不是一句空话），以及**它是本系列唯一你可以自己去 GitHub 上核对代码与授权状态的对象**。核对结果是：**能查，但比宣传的弱**，数据在后面。月付基础版 €1.1 起，是全系列门槛最低的。

**不进打分表。** 它没有订阅链接、没有节点地区清单、没有倍率、不套 Clash / Mihomo，与 [总览篇](README.md) 那 6 家不在同一个坐标系里，硬打分会造成假可比。

## 二、这张表里有两个必须说清的反差

1. **挂着 GPL-3.0、3038 星的那个仓库，最后一次提交停在 2025 年 2 月。** 也就是说，被广泛引用为"迷雾通开源"的那份代码，已经一年多没动了。
2. **现在活跃的开发线是 `geph5`（2026-09-14 仍在提交），而它没有声明任何开源许可证**；安卓端、桌面 GUI、iOS 端同样未声明许可证。

**结论**：说迷雾通"开源可审计"，在历史上（geph4 客户端，GPL-3.0）成立；**在当前版本线上并不严谨**——没有许可证声明意味着代码虽公开可见，但授权与再分发权利并未明确。另外，**服务端（bridge 与出口）本来就不在这些仓库里**，所以"零日志""不记录流量"这类承诺，仍然只能靠它的公开文档与第三方审计，不能靠读客户端代码证明。

这不是要贬低它。**恰恰相反**：一家愿意把仓库摆出来、让你能查出"上一版是 GPL、这一版没写许可证"的厂商，比那些只给你一句"没有后台日志，让隐私更安全"（本系列某家套餐卡原文）却什么都查不了的站，可验证程度高得多。

## 三、它和机场的实际差别

| | 机场（本系列 6 家） | 迷雾通 |
| --- | --- | --- |
| 交付物 | 订阅链接，导入 Clash / Shadowrocket | 自家客户端，开箱可用 |
| 主要目标 | 提速、解锁流媒体与 AI | **在封锁下建立连接** |
| 出口质量 | 由线路与 IP 类型决定（机房 / 家宽 / 原生） | 取决于分配到的出口，用户不可选地区 |
| 换供应商成本 | 换订阅链接 | 换软件，且旧配置不通用 |
| 可审计性 | 几乎为零 | 客户端代码公开（见上表） |

**对学生党的实际意义**：如果你所在的网络环境经常整段连不上（校园网、教育网出口），迷雾通这类抗规避系统的价值在于"连得上"；而如果你要的是"连得上且 AI 不降智、能看 4K"，那还是要看线路与 IP 类型——**这两件事不是同一个问题**。

## 五、它最大的结构特征：绑定设备，不是绑定账号

★ 这是博主指出的、也是我认为迷雾通和所有机场最本质的一处不同：**它的授权对象是"设备"，不是"账号"。**

这件事有两面，都得说：

**正面：它把"仅限本人使用"从一句条款变成了一种机制。** 回看本系列其他家怎么表达同一件事——

| 站 | 官方说法 | 靠什么执行 |
| --- | --- | --- |
| 一元机场 | 套餐卡写"仅限本人使用" | **只有文字**，技术上无法约束 |
| SakuraCat | "最多 3 个不同公网来源 IP 同时连接" | 数公网 IP，**同一 Wi-Fi 下全家设备算 1 个** |
| 吹雪云 | 8 / 10 / 20 / 30 / 50 台设备 | 数设备数，档位越高越多 |
| 飞猫云 | "不限制设备连接数量" | 不限制 |
| **迷雾通** | **授权绑定到设备** | **结构上就限制了共享** |

**对学生党的实际含义**：① 借同学账号、把号发给室友，这类操作在迷雾通这里不是"违反条款"，而是**根本做不到**——这比一元的"仅限本人"实在得多；② 换手机、重装系统会占用新的设备位，**买之前先问清楚解绑怎么算**（这条我没采集到，见上一节）；③ 宿舍或课题组要共用，得按设备数买，不能靠一个账号。

**反面：绑定设备意味着厂商能把"你的设备"和"你的订阅"稳定关联起来。** 这和"零日志""隐私优先"的宣传之间存在真实张力——**它防的是共享，不是记录**。开源客户端可以查它在你这一侧采集什么（见第一节那张表，geph4 确为 GPL-3.0），但**服务端不开放，绑定信息怎么存、存多久、给谁看，仍然只能靠它自己的承诺与第三方审计**。

**结论**：如果你要的是"防共享、防止号被借走"，设备绑定是优点；如果你要的是"厂商无法把我这台机器和我的身份长期关联"，那这条恰恰要计入成本。**别把"开源"和"匿名"混为一谈，这是两件事。**

## 六、适合谁

| 适合 | 不适合 |
| --- | --- |
| 网络环境经常整段不可用、需要"先连得上"的人 | 想按地区选出口（美 / 日 / 新）的人 |
| 在意可审计性、希望供应商代码公开 | 要 4K 流媒体与 AI 稳定不降智（那该看线路与 IP） |
| 不想折腾订阅与配置文件的新手 | 需要多设备自由分配、宿舍合用（授权绑设备） |
| **不想把号借出去、也不想被人借用的人**（设备绑定替你执行） | 指望"开源 = 匿名"的人（服务端不开放） |
| 把它当**兜底通道**与机场并备 | 把它当机场的替代品 |

本系列的实用建议：**主力机场 + 一个兜底通道**。投稿、传代码、赶 deadline 时单点故障代价太高，而这两类东西恰好互为备份。
